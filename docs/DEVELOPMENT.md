# 开发说明

## 1. 项目目标

当前目标不是制作传统的 Hero + CTA + 卡片墙作品集，而是先完成一套具有个人识别度、可继续扩展的作品集骨架。

- 首页：像一张可以交互的实验性平面海报。
- 作品索引：像理性、清晰、可检索的个人数据库。
- 项目详情：未来允许恢复每个项目自己的视觉语言。

## 2. 设计系统

### 视觉骨架

- 冷白 / 纯白背景与纯黑文字。
- 大字号现代无衬线与极小 Mono 辅助信息形成尺度反差。
- 以严格网格支撑有意识的错位、覆盖、越界与不规则留白。
- 钴蓝、青蓝、玫红、正红、清亮绿和明橙仅用于重点物件与状态。

### 核心视觉

首页核心物件是机场安检扫描中的透明青蓝色手提旅行包。包体与笔记本、工牌、耳机、手机、充电设备等内部物件保持独立透明 PNG，以支持 Hover、Parallax 和后续动画。

包体后方使用从正上方俯视的横向传送带。背景只保留非常浅的冷灰扫描噪点和少量连续渐隐 Halftone，不恢复无意义的蓝色环线。

### 交互原则

- 动效必须帮助理解层级、空间或状态。
- 桌面端只使用轻量视差和作品索引 Hover。
- 尊重 `prefers-reduced-motion`。
- 不使用随机科技线、光效或复杂装饰动画。

## 5. 开发流程

1. 读取 `AGENTS.md` 与 `PROJECT_MEMORY.md`，确认已锁定的设计判断。
2. 在现有网格和视觉系统内修改，避免退回通用作品集模板。
3. 图片修改只影响用户指定部分，不擅自替换已确认的包体、物品和颜色。
4. 在桌面端、移动端和 Reduced Motion 模式检查布局与交互。
5. 更新当天 `worklog/YYYY-MM-DD.md`，记录目标、改动文件、验证和下一步。
6. 检查待提交文件和敏感信息，再提交到 Git。
7. GitHub 远端可用时推送，以 README 和日志展示实时进度。

## 6. 每日整理规则

- 只提交项目源文件、正式素材、说明文档和工作日志。
- 不提交系统文件、编辑器缓存、临时目录、本地服务器日志或密钥。
- 不为了“整理”随意移动现有图片；任何路径调整必须同步更新代码引用。
- 当天没有有效变更时不制造空提交。
- 自动化发现冲突、敏感文件或无法验证的改动时停止推送并报告。
